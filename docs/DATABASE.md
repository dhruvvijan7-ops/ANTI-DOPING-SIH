# Database

**Last updated:** 2026-09-01

PostgreSQL 16, schema managed through SQLAlchemy 2.x models and Alembic migrations.
All schema changes are version-controlled in the repository — a fresh clone can
recreate the database without relying on any developer's local state.

---

## 1. Overview

- **Engine:** PostgreSQL 16 (`postgres:16-alpine` in Docker Compose).
- **ORM:** SQLAlchemy 2.x (`from app.db.session import Base, SessionLocal, engine, get_db`).
- **Migrations:** Alembic, scripts under `backend/migrations/versions/`.
- **Host port:** by default 5432; this development machine uses
  `POSTGRES_HOST_PORT=54320` (see `.env`).

Connection string: `DATABASE_URL` (e.g.
`postgresql+psycopg://clean_sport:clean_sport@localhost:54320/clean_sport`).

## 3. Initialization

```bash
# from backend/
alembic upgrade head
```

Environment prerequisites: a reachable PostgreSQL instance and `DATABASE_URL`
configured (via `.env` or environment).

---

## 4. Migrations workflow

Generate a new migration after adding/changing models:

```bash
alembic revision --autogenerate -m "descriptive_message"
alembic upgrade head
```

Review autogenerated migrations before applying. Check history/state with:

```bash
alembic current
alembic history
```

---

## 5. Seed data

- Development RBAC roles and users are seeded on backend startup when
  `DEPLOY_INITIAL_USERS=true` and `APP_ENV=development` (see `app/db/seed.py`),
  idempotently.
- Domain/synthetic seeding (deterministic generator, 9 known scenarios,
  `seed-data` / `reset-data` operations) is planned in STAGE C.

---

## 6. Synthetic data

- Prototype data is **synthetic only** (D-006, §25). No real personal or sensitive
  information is ever stored or committed.
- A deterministic generator (fixed seed) is planned under `scripts/` so datasets are
  reproducible and scenario-separated for analytical validation.

## 8. Tests

`tests/conftest.py` provisions a separate test database (`clean_sport_test`) and runs
migrations + seed so tests are self-contained. Note: the test-DB URL currently
defaults to `localhost:5432` and must be aligned with the configured host port
(`54320`) before STAGE B test runs.
